Aarch64基础知识

寄存器Registers

通用寄存器 X0–X30

AArch64 有 31 个 64 位通用寄存器，编号 X0 到 X30。它们的低 32 位可以单独用 W0–W30 访问。在函数调用中，它们有明确的分工：

  • X0–X7：用于传递函数参数，以及存放函数返回值。其中 X0 专门用作返回值寄存器。超过 8 个的参数会通过栈传递。

  • X8：间接结果寄存器。如果函数返回一个较大的结构体，调用者会分配好内存，并把指向该内存的指针放在 X8 里传进去。

  • X9–X15：临时寄存器（Caller-saved）。被调用的函数可以随意使用它们，不需要保存和恢复。

  • X16 (IP0) / X17 (IP1)：过程间调用临时寄存器。链接器在生成跳转“胶合代码”时可能会用到它们。

  • X18：平台寄存器。在 Linux 上一般可用，但在 Darwin/Windows 平台上被保留，写可移植代码时最好避开。

  • X19–X28：被调用者保存寄存器（Callee-saved）。如果被调用的函数要使用它们，必须先保存到栈上，并在返回前恢复原值。

  • X29 (FP)：帧指针。通常指向当前函数栈帧的基址，方便调试和栈回溯。

  • X30 (LR)：链接寄存器。执行 bl 调用时，硬件会自动把返回地址存到这里。这就是为什么 ret 默认跳回 X30 的原因。

特殊寄存器

  • SP (Stack Pointer)：栈指针。在 AArch64 中，SP 不再是通用寄存器，而是专用寄存器，并且强制要求 16 字节对齐。

  • PC (Program Counter)：程序计数器。指向当前指令地址，但你不能像访问通用寄存器那样直接用指令读写它。

  • XZR / WZR：零寄存器。读它永远得到 0，写它会被忽略。常用来快速清零或丢弃不需要的结果。

  • PSTATE / NZCV：处理器状态。AArch64 没有传统的 CPSR，而是把状态拆成了独立的字段。其中 NZCV 四个标志位（负数、零、进位、溢出）在条件分支和比较指令中非常关键，可以通过 MSR/MRS 指令访问。

SIMD / 浮点寄存器 V0–V31

这 32 个 128 位寄存器用于浮点和 NEON SIMD 运算。

基本指令

**mov **- 与 x86 指令类似，将一个寄存器的值复制到另一个寄存器。它也可以用于加载立即数。 

language
mov x0, x1; copies x1 into x0
mov x1, 0x4141; loads the value 0x4141 in x1

str/ldr - 存储和加载寄存器。本质上是根据给定的指针存储和加载寄存器中的数据。

language
str x0, [x29]; store x0 at the address in x29
ldr x0, [x29]; load the value from the address in x29 into x0

**stp/ldp **- 存储和加载一对寄存器。与 str/ldr 类似，但对象是一对寄存器。

language
stp x29, x30, [sp]; store x29 at sp and x30 at sp+8

**bl/blr **- 分支链接（指向寄存器）。x86 架构的等效函数是 call。它本质上是跳转到子程序并将返回地址存储在 x30 寄存器中。

language
blr x0; calls the subroutine at the address stored in x0

**b/br **- 分支（指向寄存器）。x86 等效命令是 jmp。它本质上是跳转到指定的地址。

language
br x0; jump to the address stored in x0

call 和 jmp 的核心区别在于：call 会保存返回地址，jmp 不会。

*1. jmp（跳转）*

language
jmp label

  • 只改 rip（指令指针），直接跳到目标地址继续执行。

  • 不保存任何返回地址，所以跳过去之后，CPU 不知道原来是从哪来的，没法自动回来。

  • 用途：循环、if/else 分支、goto、尾调用优化等。

*2. call（调用）*

language
call label

  • 做两件事：

    1. 把下一条指令的地址（返回地址）压入栈（x86-64 上是压 rip 的下一条，即 call 指令之后那条指令的地址）。

    2. 跳到目标地址。

  • 配合 ret 使用：ret 从栈里弹出返回地址，跳回去，实现“调用—返回”。

**ret **- 与从堆栈中弹出返回地址的 x86 等效函数不同，它会在 x30 寄存器中查找返回地址并跳转到那里。

x86：从栈中弹出

x86 的 ret 是一条隐式使用栈的指令。它的操作逻辑是：

  1. 从当前栈顶（[rsp] 或 [esp]）读取返回地址。

  2. 将栈指针上移（弹出该地址）。

  3. 跳转到读到的地址继续执行。

这也意味着，在 x86 上如果你能控制栈上的内容，你就能控制 ret 的去向，这是经典栈溢出利用的基础。此外，ret 还可以带一个立即数参数（如 ret 8），在返回后额外释放栈上的参数空间。

AArch64：从寄存器跳转

AArch64 的 ret 本质上是一条“带返回提示的寄存器跳转指令”。它的默认操作是：

  • 直接跳转到 X30（LR，链接寄存器） 中保存的地址。

  • 它不访问栈来获取返回地址。返回地址是在执行 bl（带链接分支）指令调用函数时，由硬件自动写入 X30 的。

索引模式Indexing modes

与 x86 不同，Aarch64 中的加载/存储指令有三种不同的索引“模式”来索引偏移量：

  1. Immediate offset : [base, #offset] - 直接对偏移量进行索引，不要做任何其他操作。
language
ldr x0, [sp, 0x10]; load x0 from sp+0x10
  1. Pre-indexed : [base, #offset]! - 与上述几乎相同，只是将基址+偏移量写回基址。
language
ldr x0, [sp, 0x10]!; load x0 from sp+0x10 and then increase sp by 0x10
  1. Post-indexed : [base], #offset - 直接使用基址，然后将基址+偏移量写回基址
language
ldr x0, [sp], 0x10; load x0 from sp and then increase sp by 0x10

堆栈和调用约定

寄存器 x0 到 x7 用于向子程序传递参数，额外的参数则通过堆栈传递。返回地址存储在 x30 中，但在嵌套子程序调用期间，它会保留在堆栈上。x30 也被称为链接寄存器。x29 寄存器也称为帧指针，其 x86 等效寄存器为 ebp。栈上的所有局部变量都是相对于 x29 访问的，并且它保存着指向前一个栈帧的指针，就像在 x86 中一样。

这里要澄清一个容易误解的点：AArch64 的栈是向低地址增长的，函数内局部变量在低地址，保存的 x29/x30 和返回地址在更高的地址

可以看一个例子来说明

language
.text:0000000000400818
.text:0000000000400818 ; =============== S U B R O U T I N E =======================================
.text:0000000000400818
.text:0000000000400818 ; Attributes: bp-based frame
.text:0000000000400818
.text:0000000000400818 ; __int64 __fastcall main(__int64, char **, char **)
.text:0000000000400818 main                                    ; DATA XREF: start+18↑o
.text:0000000000400818                                         ; .text:off_400640↑o
.text:0000000000400818
.text:0000000000400818 var_s0          =  0
.text:0000000000400818
.text:0000000000400818                 STP             X29, X30, [SP,#-0x10+var_s0]!
.text:000000000040081C                 MOV             X29, SP
.text:0000000000400820                 BL              sub_400760
.text:0000000000400824                 ADRL            X0, aName ; "Name:"
.text:000000000040082C                 MOV             X2, #5  ; n
.text:0000000000400830                 MOV             X1, X0  ; buf
.text:0000000000400834                 MOV             W0, #1  ; fd
.text:0000000000400838                 BL              .write
.text:000000000040083C                 ADRL            X0, unk_411068
.text:0000000000400844                 MOV             X2, #0x200 ; nbytes
.text:0000000000400848                 MOV             X1, X0  ; buf
.text:000000000040084C                 MOV             W0, #0  ; fd
.text:0000000000400850                 BL              .read
.text:0000000000400854                 BL              sub_4007F0
.text:0000000000400858                 MOV             W0, #0
.text:000000000040085C                 LDP             X29, X30, [SP+var_s0],#0x10
.text:0000000000400860                 RET
.text:0000000000400860 ; End of function main

这边主要关注1、2、8、9这几个步骤。

  1. 进入 main 时（0x400818 之前）
language
SP  = S              ; 16 字节对齐
X29 = 旧帧指针
X30 = start 中 BL main 的下一条地址（返回地址）
  1. STP X29, X30, [SP,#-0x10]!（0x400818）

前索引写回：先 SP = SP - 0x10，再存。

language
SP  = S - 0x10
[S - 0x10]     = 旧 X29
[S - 0x10 + 8] = 旧 X30   ← 返回地址被保存到栈上X29、X30 寄存器本身不变

此时栈布局（低地址 → 高地址）：

language
S-0x10 : 旧 X29
S-0x08 : 旧 X30（返回地址）
S      : 原栈顶
  1. MOV X29, SP（0x40081C）
language
X29 = S - 0x10        ; 新帧指针指向当前栈帧基址
SP  = S - 0x10        ; 不变X30 = 旧 
X30          ; 不变
  1. BL sub_400760（0x400820）

BL 做两件事：把下一条指令地址（0x400824）写入 X30，然后跳到 sub_400760。

language
X30 = 0x400824        ; 返回地址变成 BL 的下一条
SP  = S - 0x10        ; BL 本身不改 SP
X29 = S - 0x10        ; 不变

进入 sub_400760 后，它自己会开栈帧、改 SP，但返回时 SP 会恢复成 S - 0x10，X30 会恢复成它进入时的值（即 0x400824）。所以 BL 返回后：

language
SP  = S - 0x10
X29 = S - 0x10
X30 = 0x400824        ; 被调函数返回后，X30 恢复为 BL 写入的返回地址

（严格说，被调函数返回后 X30 是它恢复的“进入时值”，也就是 0x400824。）

  1. 中间 write / read 的 BL（0x400838、0x400850）

每次 BL 都会把下一条地址写入 X30，被调函数返回后 X30 恢复成该地址。SP、X29 不受影响，仍是：

language
SP  = S - 0x10
X29 = S - 0x10
X30 = 对应 BL 的下一条（如 0x40083C、0x400854）
  1. BL sub_4007F0（0x400854）

类似

  1. MOV W0, #0（0x400858）

只改 W0（X0 低 32 位），SP/X29/X30 不变。

language
SP  = S - 0x10
X29 = S - 0x10
X30 = 0x400858
  1. LDP X29, X30, [SP+var_s0], #0x10（0x40085C）

var_s0 = 0，所以是 LDP X29, X30, [SP], #0x10：后索引写回——先从 [SP] 读 X29、[SP+8] 读 X30，然后 SP = SP + 0x10。

language
X29 = [S-0x10]        ; 恢复旧 X29
X30 = [S-0x08]        ; 恢复旧 X30（= start 里 BL main 的返回地址）
SP  = (S-0x10) + 0x10 = S
  1. RET（0x400860）

AArch64 的 RET 默认跳转到 X30：

language
PC = X30 = 旧 X30     ; 回到 start
SP = S                ; 已恢复
X29 = 旧 X29          ; 已恢复
